# 判例読解の実データ検証

検証日: 2026-10-04（JST）。モデル: 利用者指定の `openai/gpt-5.2`。本番環境へは未導入。

## 検証環境

既存のCockroachDB内に独立した `recourt_reading_validation` DBを作成し、追加マイグレーションを適用した。検証用のMiniflare WorkersはService Binding・Queue・Workflow・共有R2を使用し、外部通信はNode経由で中継した。この環境内の通常のWrangler外部fetchが失敗したための検証用構成で、製品コードには中継を追加していない。

Webは `http://localhost:15137`、検証APIは `http://127.0.0.1:19787`。標準の開発ポートを使用中の既存プロセスとは分けた。検証R2は `/private/tmp/recourt-harness/stable` に保持する。これらの一時プロセスは、本番用の起動設定ではない。

標準の `pnpm dev` は、Crawler・External・Extract・Internalを1つのWranglerへまとめ、共有R2をルートの `.wrangler/state` に保持する構成に変更した。別名・別ポートで同じ構成を起動し、独立したAPIのService Bindingから実判例一覧・140トピック・保存PDFのRange取得206を確認した。検証用R2の整合したスナップショットもこのローカル保存先へコピーしており、現在の検証DBと組で使用できる。

別の15文書を保留した（抽出不十分14、本文60,000字超1）。保留文書を一覧・件数から除外した。同一事件・同一PDF・同一処理版の検索で既存文書が返り、再登録でも `created: false` と同じ文書IDが返ることを確認した。

ローカル検証R2の再起動時に保存内容が消える問題を、Miniflareの `resourcePersistencePath` 設定で修正した。復元した30文書は公式PDFのハッシュと、再抽出・直列化した本文のハッシュがDBの値に一致した。再起動後も原文取得とPDF表示が成功した。

初期の検証で、構造化出力の途中終了と実在しない箇所IDによる生成失敗が発生した。出力枠を増やし、生成段階のIDを本文のIDの列挙型へ制限した。内容照合では最高裁事件の「原審が検討すべき点」を当事者の検討として述べる誤りを発見し、判断主体・審級・法廷意見と補足意見の区別を指示に追加した。同事件の3項目を再生成し、原審の審理不足として説明されることを確認した。

## 画面・API

- ブラウザで複数ラベルを選択し、OR条件の一覧を表示した。戻る操作でトピックを復元し、同じ判例を開き直すとタブ内の完了した会話が復元された。
- 実APIで20件のページ送り、重複事件の除外、一致トピック数→裁判日の並び順、件数、該当なしを確認した。
- 全体像の「短く・標準・詳しく」を実AIで生成した。詳しい表示中の「もっと簡単に」は今回の返答だけを短い基本値に変更し、次の通常の質問は選択中の基本値を使う。
- 「この東京高裁判決の後、上告審はどうなった？」には、提供本文で確認できないと回答し、本文外の結果を断定しなかった。
- 根拠の原文抜粋と、保存PDFの該当ページをブラウザで表示した。実APIでPDF全体200、先頭・末尾のRange 206、範囲外416を確認した。
- PDFの1ページと56ページの指定が、実際のPDFビューアの表示ページに一致した。
- 実AI配信の最初の段落を受け取ってから接続を中止した。`enable_request_signal` 設定を追加し、サーバーの `case_reading_cancelled` ログを確認した。中止を生成失敗率とは分ける。
- 別事件の文書IDを指定すると、PDF・解説とも404になりAI生成は開始されなかった。
- 自動テスト99件が通過した。無効ID・根拠欠落の拒否、切り替え時の生成中断、通信・生成失敗の再試行、破損・画像PDF・各上限、旧Queue形式の互換を確認した。
